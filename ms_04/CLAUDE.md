# MinScript v0.4

The v0.4 restart: value semantics with inferred sharing (`T` / `*T` parameters, effect summaries, `shared`, `Identity`). Everything for v0.4 lives in this folder. `../minscript/` (stage 0, v0.2) and `../stage1/` are reference only.

## Layout

- `docs/spec.md`: **the source of truth**, self-contained. Change it before or alongside any syntax or semantics change, and keep §18 (diagnostics), §19 (grammar), §20 (corpus) and §22 (open questions) in sync. `docs/spec_04_ai.md` is the design note with the reasoning (superseded, its section numbers differ); `docs/porting_notes.md` records the v0.2 → v0.4 port.
- `src/`: the compiler in TypeScript, run directly by Node ≥ 23.6 (type stripping), no runtime dependencies. Erasable TS only (no `enum`, `namespace`, parameter properties); import with `.ts`.
  - `token.ts`, `diagnostic.ts` (`Diagnostic`, `LineMap`), `lexer.ts`, `ast.ts`, `parser.ts`, `sexpr.ts` (`.ast` format), `dump.ts` (`.tokens` format), `resolve.ts` (name resolution: side tables keyed by AST node), `resolve_dump.ts` (`.refs` format), `loader.ts` (finds a program's packages, resolves them in dependency order), `types.ts` + `check.ts` (the type checker: bidirectional, gradual `unknown`), `check_dump.ts` (`.types` format), `hir.ts` (the HIR: places, resolved calls, sugar removed), `lower.ts` (AST → HIR), `witness.ts` (which type parameters each generic function needs at run time, spec §15.4), `hir_check.ts` (HIR invariants: findings are compiler bugs), `hir_dump.ts` (`.hir` format), `effects.ts` (effect summaries, bottom-up by SCC, spec §9.5 / §15.1), `access.ts` (the access check, pass 7), `mechanism.ts` (pass 8: move / share / view per use with backward liveness, owned vs borrowed parameters to a fixpoint, copy-on-write checks proven unnecessary, heap promotion; the JS back end reads its `tags` and `unique`), `lint.ts` (pass 9: the §18.4 lints and their levels; L_SHADOWED_VARIANT is recorded by the checker in `CheckResult.lints`, L_SUMMARY_WIDENED by pass 6; `frontEnd` returns them as `lints`, apart from `diagnostics`), `pipeline.ts` (the whole front end as one call), `cli.ts`, and `js/`: `emit.ts` (HIR → JS: control flow hoisted into temporaries so evaluation stays left to right, copy-on-write `$rt.u` before writes and `$rt.s` on shared reads, `*T` arguments as cells written back after the call), `runtime.ts` (values, integers, printing with float shapes, maps, tasks, `select`; `_builtin()` functions keyed by HIR name, `prelude.Vec.push`, `std.time.after`) and `run.ts` (compile + run).
  - Done: spec §21 steps 1 (lexer + parser), 2 (resolver + loader), 3 (type checker), 4 (HIR + witnesses), 5 (effect summaries), 6 (access check), 7 (the JS back end), 8 (mechanism selection) and 9 (lints). Next: step 10, std, which also unblocks the skipped run tests; step 10 (std) unblocks the skipped run tests.
  - Lowering reads the checker's recorded decisions (`types`, `calls`, `members`, `variants`, `ops`, `rets`, `declTypes` in `CheckResult`); it never re-derives a type rule. If lowering needs a fact, record it in the checker.
  - The checker reports a mismatch only between two types it fully knows; anything it can't know is `unknown`. Don't add special cases for std packages that aren't written yet.
  - Passes don't modify the AST; they return side tables keyed by node.
- `std/`: std in MinScript. `std/prelude.ms` and `std/time/` exist so far; they must load cleanly. A function whose body is only `_builtin()` needs a runtime entry under its HIR name. std packages listed in spec §14.4 but not written yet load as *not loaded* (members `unknown`), so don't add workarounds for them in the passes.
- `test/`: `errors/` (parser and lexer cases: one per function, `//~ CODE` on the line of each expected diagnostic, matched exactly), `resolve/` (each file resolved as one package: `//~` annotations, or a `.refs` snapshot when it has none), `check/` (the same, type-checked: `//~`, or a `.types` snapshot), `hir/` (lowered: a `.hir` snapshot), `effects/` (summaries: an `.effects` snapshot), `access/` (whole programs through the access check: `//~`), `parser/` (`.ast` snapshots), `lexer/` (`.tokens` snapshots), `corpus.test.ts`, `programs.test.ts`, `lint.test.ts` (`test/lint/`: one file per lint with firing and quiet cases, `//~ L_CODE`, a `//! effects-cap: N` header; `test/lint/project/` for mod.ms levels), `mechanism.test.ts` (`test/mechanism/`: a `.mech` snapshot, and a `.out` that must match with and without pass 8), `run.test.ts` (runs `examples/run/*.ms` and `examples/packages/*/` against their `.out`; a program that needs an unwritten std package is skipped by name in `NEEDS_STD`). Unit tests sit next to the code as `src/*.test.ts`.
- `examples/` (the v0.2 corpus ported to v0.4) and `samples/` (`calc`, `shop`): every program loads and resolves with exactly the diagnostics its `//~` annotations name (most have none; `examples/packages/errors/` holds the loader cases).

## Commands

`npm test`, `npm run test:update` (rewrites snapshots: review the diff), `npm run typecheck`, `npm run lex -- f.ms`, `npm run parse -- f.ms`, `npm run resolve -- f.ms`, `npm run types -- f.ms`, `npm run hir -- f.ms`, `npm run effects -- f.ms`, `npm run check -- entry...` (a file, a folder or a project), `npm run js -- entry` (the compiled JS), `npm run run -- entry` (compile and run; `--stats` prints the copies made, `--no-mech` skips pass 8), `npm run mech -- f.ms` (pass 8's choices), `npm run lint -- entry... [--deny L_X] [--allow L_X] [--strict]`.

## Rules

- Parser errors: `report()` when the intended form is clear (keep parsing), `fail()` otherwise (reports and syncs to the next statement, item, member, arm or list element). Each mistake gives exactly one diagnostic. The lexer inserts synthetic closers so the parser never sees unbalanced delimiters.
- A new lexer diagnostic code goes in `LEXER_CODES` too. Every code in spec §18.1–§18.2 must have an `errors/` test, every resolver / loader code in §18.3 a `test/resolve/` case, an `examples/packages/errors/` case or a `src/loader.test.ts` test, and every checker code a `test/check/` case, and every access code a `test/access/` case.
- A new lint goes in `LINTS` (`src/lint.ts`), spec §18.4 and a `test/lint/` file with a firing and a quiet case. Lints stay out of `FrontEnd.diagnostics`, so `//~` annotations in `examples/` don't need them.
- Pass 8 must never change what a program prints. A new move or elided check needs a case in `test/mechanism/aliasing.ms` where getting it wrong would be visible.
- MinScript code (samples, tests, spec examples) follows the spec, mixes `let` / `var` with `:=` / `:==`, and uses `x := [] as Vec[T]` as freely as `let x: Vec[T] = []`.
