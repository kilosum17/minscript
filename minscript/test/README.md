# MinScript test corpus

The syntax under test is defined by [docs/spec.md](../docs/spec.md) (v0.2). The old samples written in pre-v0.2 syntax are in [docs/history/samples](../docs/history/samples).

| Folder | What it tests | Expected output |
|---|---|---|
| `lexer/` | tokenization: numbers, strings, sigils, operators, comments, keyword rules | `*.tokens` snapshot (generated by the lexer, reviewed by hand) |
| `parser/` | one feature per file: declarations, expressions, closures, generics, control flow… | `*.ast` snapshot (S-expressions, generated by the parser, reviewed by hand) |
| `errors/` | lexer/parser diagnostics, annotated inline | the `//~` annotations: every code, on its line, and nothing else |
| `programs/` | realistic multi-feature programs | must pass every pass (lex, parse, resolve, type-check, ownership) with **zero** diagnostics |
| `resolve/` | name resolution: scopes, shadowing, captures, imports, resolver errors | `//~` annotations, plus a `*.refs` snapshot of what every name binds to |
| `check/` | type checking: inference, coercions, calls, patterns, checker errors | `//~` annotations, plus a `*.types` snapshot of every binding's inferred type |
| `ownership/` | moves, mutability, scoped values, escaping closures, borrows across spawn | `//~` annotations (`valid.ms` must have none) |
| `hir/` | lowering: one case per desugaring | a `*.hir` snapshot of the lowered program |
| `run/` | programs run on the JS back end | a `*.out` snapshot of what they print (programs in `programs/` with a `.out` file run too) |
| `projects/` | projects (spec §17): `mod.ms` evaluated, `main` = every `package main` file of its folder, `path:` deps, scripts | `config.json` (the evaluated `Config`) and `run.out`; `script_in_eval` must fail with `E_SCRIPT_IN_EVAL` |
| `packages/` | programs of several packages (`app.x`, `./x`, std), loaded by `src/loader.ts` from each `main.ms` | `//~` annotations in any file of the program; without any, a `main.out` snapshot of the run |

## Conventions

- Every file is a complete compilation unit: it starts with `package …` and only has items at the top level.
- Comments like `// (+ 1 (* 2 3))` give the intended structure in S-expression form. They are notes for whoever writes the `.ast` snapshot later.
- **Error annotations:** `//~ CODE` means the diagnostic `CODE` must be reported **on that line**. `//~ CODE CODE2` means both must be.
  - The parser must report every annotated diagnostic and no others.
  - The harness finds annotations by scanning the **raw source text**, so an annotation still counts when it sits inside an unterminated string or comment (see `errors/literals.ms` and `errors/unterminated_comment.ms`).
  - Each error case sits in its own top-level function, so the parser can recover at the next item and keep going.
- Cases where recovery isn't reliable (an unmatched delimiter, an unterminated block comment) get a file of their own.
- `errors/` only covers diagnostics that the lexer or parser can detect. Resolver diagnostics go in `test/resolve/` (each file there must parse cleanly), and type-checker diagnostics (e.g. `E_CANNOT_INFER_GENERIC`) will go in `test/check/`.
- File names are `snake_case.ms`.

## Running

```bash
npm test               # unit tests (src/*.test.ts) + corpus (test/corpus.test.ts)
npm run test:update    # rewrite the .tokens / .ast snapshots, then review the diff
npm run lex -- test/lexer/strings.ms       # print a token dump
npm run parse -- test/parser/closures.ms   # print the AST
npm run resolve -- test/resolve/scopes.ms  # print what every name binds to
npm run check -- test/check/errors.ms      # type-check + ownership, print diagnostics
npm run hir -- test/hir/lowering.ms        # print the lowered HIR
npm run js -- test/run/basics.ms           # print the generated JS
npm run run -- test/run/basics.ms          # compile and run on Node
ms run test/projects/basic                 # with `ms` on the PATH (`npm link` in minscript/): see `ms help`
```

`test/corpus.test.ts` checks that:
- every `lexer/*.ms` parses with zero diagnostics and matches its `.tokens` snapshot;
- every `parser/*.ms` parses with zero diagnostics and matches its `.ast` snapshot;
- every file in `programs/` parses with zero diagnostics;
- in `errors/`, the lexer alone reports exactly the annotated lexer codes, and lexer + parser report exactly all the annotated codes, each on its annotated line;
- every file in `programs/` also resolves with zero diagnostics;
- every `resolve/*.ms` parses cleanly, the resolver reports exactly its annotated codes, and its `.refs` snapshot matches;
- `std/prelude.ms` and every file in `programs/` type-check with zero diagnostics;
- every `check/*.ms` parses and resolves cleanly, the checker reports exactly its annotated codes, and its `.types` snapshot matches;
- every `ownership/*.ms` type-checks cleanly and the ownership pass reports exactly its annotated codes;
- every file in `programs/` also passes the ownership pass with zero diagnostics;
- every `hir/*.ms` passes every check and matches its `.hir` snapshot;
- every valid file lowers to HIR that `validateHir` accepts: every local bound, every label valid, nothing unsupported;
- every valid file compiles to JS that loads;
- every `run/*.ms`, and every program with a `.out` file, runs without panicking and prints exactly its `.out`.

**`.hir` format:** S-expressions, one top-level form per type and function. `(do …)` is a block, `(let x: T v)` / `(var …)` is a binding, `$name` is a temporary from lowering, and `x'2` is a second local named `x` in the same function. `@name` is a global, `#name` a function value, `(dyn r m …)` a dynamic call, and `extern:path` a member of a package without signatures. `(ok v)` / `fail` match an Option or a Result.

**`.types` format:** one line per binding (local, parameter, closure parameter, pattern binding, implicit `it` at its first use), in source order: `line:col  name: type`, followed by any diagnostics. Types print as in the spec: `int`, `Vec[string]`, `User?`, `t(int, string)`, `(int, int) -> int`, `{integer}` for an unresolved literal.

**`.refs` format:** one line per use, in source order: `line:col  name → target`.
- The target is the declaration's `line:col` and kind (`local`, `param`, `closure-param`, `fun`, `type`, `union`, …), or `builtin`, `prelude`, `this`, `implicit it`, `package "std.json"`, `import "std.io.println"`, or `deferred` (left for the type checker).
- `closure captures a@3:5, b@4:9` lines list each closure's captures.
- Any diagnostics come last.

**`.ast` format:** the AST as S-expressions, in the notation of the corpus comments: `(+ 1 (* 2 3))`, `(call (. x abs))`, `(as v (Option i32))`. Forms longer than 100 columns are broken onto indented lines. For the less obvious forms:
- statements: `(let p T v)`, `(var …)`, `(:= x v)`, `(:== x v)`, and `(; e)` for `e;`;
- expressions: `(paren e)`, `(template "a" x "b")`, `(struct T fields…)`, `(_ fields…)` for `_{}`, `(generic f T…)` for `f.[T]`, `(? e)` for postfix `?`;
- types: `(& T)` / `(&mut T)` for borrows, `(fn (params A…) R)`, `(t A B)` for tuples, `(r fields…)` for records, `(and A B)` for intersections, `(| A B)` for literal unions.

**`.tokens` format:** one token per line: `line:col`, a flag, the kind, the value, then `"""` for a multi-line string and `→ line:col` for an opener's matching closer.
- The flag is `nl` for a newline before the token, `ws` for whitespace or a comment before it, and blank when the token is glued to the previous one.
- After the tokens come the trivia (comments), then any diagnostics.
